# 即时通讯接管对象选择设计

## 背景

当前工具默认只面向企业微信：窗口吸附、状态检测、聊天读取和快捷发送都直接依赖“企业微信”的进程名与 AX 树结构。新需求是在 macOS 上读取已安装的即时通讯软件，优先支持大象、微信、企业微信，让用户选择当前要接管的对象。

## 目标

- 扫描 macOS 已安装的即时通讯客户端，优先识别大象、微信、企业微信。
- 只把有本地适配器的客户端作为可选择对象展示；未运行时仍显示，但提示用户先打开。
- 当前目标由用户在面板中选择，后续窗口吸附、状态检测、聊天读取和发送都走这个目标。
- 不把不同客户端的 AX 结构写在同一个流程里；每个软件的差异必须隔离在自己的适配器中。
- 保持企业微信现有可靠链路为默认行为。

## 非目标

- 不调用任何即时通讯软件的网络接口。
- 不修改任何即时通讯软件进程。
- 第一版不承诺微信和大象的完整发送/读取已验证成功；若 AX 树尚未验证，必须以“待验证”状态呈现，而不是假装可用。
- 不自动接管所有已安装聊天软件。

## 设计

新增 `im_clients` 包，提供一个稳定接口和注册表：

- `base.py`：定义 `IMClientAdapter`、`IMClientStatus`、`TakeoverCapability` 等基础数据结构。
- `registry.py`：集中注册已支持的客户端，并提供 `discover_clients()`、`get_selected_client()` 等查询入口。
- `wechat_work.py`：封装现有企业微信能力，迁移当前 `sender.py` 中和进程名、AX 树有关的逻辑。
- `wechat.py`：微信适配器，第一版负责安装/运行发现、激活、窗口边界读取，发送/读取标记为待验证。
- `daxiang.py`：大象适配器，第一版负责安装/运行发现、激活、窗口边界读取，发送/读取标记为待验证。

GUI 顶部状态区增加“接管对象”下拉选择。列表显示三个优先客户端，名称后附状态：已连接、未运行、待验证、未安装。默认选择企业微信；如果企业微信未安装但其他客户端可发现，则选择第一个已安装目标。

## 数据流

1. 启动 GUI 时调用 `discover_clients()`。
2. 注册表扫描 `/Applications`、`~/Applications` 和 `NSWorkspace` 当前运行应用。
3. GUI 选择一个 `client_id` 作为当前接管对象。
4. 状态检测、窗口吸附、聊天读取、发送统一调用当前适配器。
5. 适配器内部处理各自软件的进程名、bundle id、AX 树查找、发送限制和错误提示。

## 错误处理

- 未授权辅助功能：保留现有权限提示。
- 未安装：下拉中显示但不可作为“已连接”状态。
- 未运行：允许选择，状态提示“请先打开”。
- 待验证能力：阻止发送或读取，并提示该客户端接管能力仍需验证。
- 企业微信异常：继续沿用 `NoChatWindowError` 等现有错误语义。

## 测试

- 单元测试覆盖客户端发现：已安装、正在运行、未安装、待验证能力。
- 单元测试覆盖默认选择：优先企业微信，否则选择第一个已安装的受支持客户端。
- GUI 测试覆盖目标选择后发送/读取调用当前适配器，而不是固定企业微信函数。
- 语法检查覆盖 `gui_panel.py`、`sender.py` 和新增 `im_clients` 模块。
